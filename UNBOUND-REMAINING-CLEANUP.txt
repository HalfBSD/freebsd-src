HalfBSD Unbound: remaining cleanup assessment
Date: 2026-10-11
Scope: repository source review after configuration consolidation; no new removals
or native verification performed for this report.

FIRST: STABILIZE ON ANVIL

Buildworld/buildkernel, installworld and etcupdate must pass on native HalfBSD
before another reduction pass. Verify boot ordering, effective IPFW rules,
localhost/LAN UDP and TCP DNS, cache hits and negatives, local A/PTR/CNAME,
DNSSEC success/bogus handling, root.key ownership and updates, ordinary/fast
reload, TCP quotas, provider failover/recovery and complete upstream outage.
The shipped IPFW workstation policy intentionally allows SSH TCP 22 and DNS
UDP/TCP 53 from any source unless optional LAN restrictions are configured.
Do not describe the current default as LAN-only or externally blocked.

Configuration now defaults to /etc/unbound/unbound.conf and /var/unbound/root.key,
with runtime files in /var/run. Default chroot is disabled; optional core chroot
support remains. No native proof of boot, ownership or packet filtering exists
from the Linux regressions. UNBOUND-CONFIGURATION-HANDOFF.txt records details.

NEXT INDEPENDENT REMOVALS

1. Authority zones and transfer/update machinery.
   services/authzone.c/.h are retained and compiled. Remove auth-zone parser,
   AXFR/IXFR/NOTIFY/update scheduling, transfer sockets, ZONEMD/zone-file loaders
   and authority-only administration/statistics together after tracing callers.
   Preserve localzone.c ordinary local-zone/local-data/PTR functionality.
   Replace authority-zone regression cases with retained local-record cases;
   keep shared DNS parser, CNAME, DNSSEC and transport tests.

2. Stub zones.
   Stub-zone parsing and hint/iterator integration remain. Trace iterator and
   hints dependencies first: remove stub-specific state and commands, preserving
   shared forwarding retries, upstream selection, CNAME processing and DNSSEC.
   Do not delete shared iterator/hints code solely because its name suggests
   recursive resolution. The compiled provider hierarchy must remain unchanged.

3. IPsec and ipset remnants.
   modstack.c still contains conditional ipsecmod/ipset loader references;
   configparser.y contains their directives. ipset/ipset.c/.h, README.ipset.md
   and Makefile.in rules remain. ipsecmod/ipsecmod.c/.h and its whitelist
   implementation also remain. These optional module sources and their parser/
   build references need physical removal, not merely disabled compilation.
   Remove independent implementations and orphaned directives/loaders/docs,
   including local-zone ipset policy, without changing IPFW itself or ordinary
   local-zone behavior. No new build switches or accepted no-op directives.

4. EDNS client-string metadata.
   Per-network labeling of upstream requests remains in configuration and the
   shared EDNS path. It is metadata, not the removed DNS client authorization
   stage. Remove the labeling feature independently while retaining ordinary
   EDNS, DNS Cookies, DNSSEC flags and TCP/truncation fallback.

5. NAT64 transport and IPv6 scope review.
   do-nat64/nat64-prefix remain in the parser and transport infrastructure.
   Evaluate NAT64-only address translation separately from IPv6 protocol support,
   AAAA records and IPv6-capable forwarding/TCP limits. DNS64 synthesis is already
   removed; its removal does not prove NAT64 transport has been removed.

SHARED INTERNALS AND LIBRARIES: INVESTIGATE BEFORE DELETING

libunbound remains a required link dependency of the four native utilities,
including local-unbound-anchor. Their Makefiles explicitly use LIBADD=unbound.
Do not remove the library based only on an apparent lack of unrelated consumers.
Audit the complete tree, installed packages and anchor internals before trimming
client APIs, asynchronous helpers or auxiliary library objects. Distinguish
installed native utilities from additional portable Makefile targets.

General recursive iterator internals remain shared with forwarding. Prune only
cleanly separable paths, with forwarding, DNSSEC, cache, retry, error and CNAME
regressions. Prefer retaining mature shared algorithms to a resolver rewrite.
The catch-all forwarding policy and prohibition of recursive fallback remain
required regardless of how much recursive-capable infrastructure is retained.

CONFIGURATION, PACKAGING AND DOCUMENTATION DEBT

- Keep migration support until existing installations have successfully moved.
  It is currently necessary upgrade code, not removable compatibility clutter.
  Later retire legacy fragment/chroot migration and obsolete-option regression
  fixtures only after defining a supported upgrade boundary.
- Review eliminating the setup helper after native defaults and anchor bootstrap
  are stable. Any replacement must preserve manual records, mutable trust state,
  rc.conf overrides, idempotence and safe validation/restart ordering.
- Review uninstalled foreign-platform init/package samples, Windows scaffolding,
  portable auxiliary targets and optional dependencies. Some still describe the
  former jail layout or create mounts/copies. They are not HalfBSD installation
  paths. Remove unused assets only after confirming consumers; do not recreate
  their old machinery in HalfBSD.
- Keep generated lexer/parser files, configure, generated headers and manual
  pages synchronized with their source templates. Audit with native Clang's
  warning settings: GCC does not flag every increment-only vestigial variable.
- Do not delete valuable protocol regressions with feature-specific fixtures.
  The upstream testcode/testdata directories are absent from this reduced tree;
  portable Makefile test targets still mention them and should be audited.
- Historical changelogs and old handoffs describe previous states. Preserve
  history but clearly point current instructions to the latest implementation.

SECURITY AND RESOURCE MANAGEMENT

Preserve DNSSEC, authenticated upstream TLS, remote-control authentication,
privilege dropping, packet validation, DNS Cookies, resource limits and TCP
quota accounting. Source-aware resource-abuse controls are not DNS client ACLs.
Review optional control/statistics complexity independently from authentication.

Capsicum is a separate investigation, not an automatic next change. Inventory
post-init configuration/CA/key reads, log reopening, anchor atomic writes and
renames, outgoing sockets, reload operations and runtime local-record/forwarder
changes. Determine whether bounded capabilities suffice before proposing any
broker or extra daemon. Compare its complexity and containment against the
now-documented loss of default chroot. No Capsicum implementation is authorized
by this report.

MEASUREMENTS AND WORKFLOW

For each future removal record physical files/lines deleted, build objects and
external dependencies removed, executable/library sizes and native versus Linux
results. Compile all four utilities and run forwarding.py, providers.py,
setup.py with BUILD, and tcp-limits.py. Add tests for affected shared behavior.
Perform one independent removal at a time; no disabled implementations, profiles,
compatibility shims or algorithm rewrites. Keep security-fix imports practical.

This report supplements the user-maintained unbound_next_steps.txt, which was
included unchanged. Proposed cleanup is not implementation or authorization to
remove those features now. The ISP DNS failure remains an unresolved diagnostic
history item; its cause must not be asserted without evidence.
