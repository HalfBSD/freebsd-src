HALFBSD UNBOUND: RPZ AND RESPONSE-IP REMOVAL HANDOFF
Date: 2026-10-11
Base: 0ff7ff5de0f8 (Use built-in prioritized DNS forwarders for HalfBSD)
Status: Implemented and tested. This report accompanies the implementation commit. Nothing pushed.

SCOPE AND SEQUENCE

The user authorized deletion of RPZ callbacks and policy-only blocks in
iterator.c, preserving ordinary resolution algorithms. RPZ was removed first.
All four utilities compiled and the forwarding and provider suites passed
before response-IP removal began. Response-IP was then removed and tested as
an independent second stage. Neither stage introduces build options, disabled
implementations, compatibility shims, or a replacement policy abstraction.

RPZ REMOVAL

Deleted services/rpz.c and services/rpz.h, including QNAME, client-address,
response-address, nameserver-name and nameserver-address triggers; policy
synthesis; passthrough state; policy actions; logging; and policy statistics.
Deleted contrib/drop2rpz and its support documentation.

Removed the three RPZ-only blocks in iterator.c: before cache lookup, before
upstream selection, and after ordinary CNAME processing. Ordinary CNAME
handling, query restarts, delegation/response processing, DNSSEC, caching,
timeouts, target selection and retries remain. A subsequent mechanical edit
removes the obsolete client-policy argument to attach_sub; its resolution
behavior is unchanged. No unrelated iterator algorithm was changed.

Removed RPZ mirrors and linked-list locks from authority-zone storage and
updates, while preserving authority-zone loading, transfers, ZONEMD and ordinary
zone data. Removed RPZ-specific DNSSEC validation bypasses for synthesized
answers and DS/DNSKEY lookups. DNSSEC now always follows ordinary validation.
Removed RPZ configuration fields, grammar/lexer entries and generated entries,
control commands, statistics fields/printers, reload structures and documentation.

RESPONSE-IP REMOVAL

Deleted respip/respip.c and respip/respip.h. Removed module registration and
callback whitelists, response-ip/response-ip-data/response-ip-tag configuration,
policy address trees, reload swaps, per-client mesh policy state, policy logging,
and memory statistics, including the metrics.awk output for the removed module.
Removed build source/object/header references from Makefile.in and the native
lib/libunbound/Makefile. No external library dependency belonged to either
subsystem, so the shared TLS and other linked libraries remain.

Removed policy-only partial-CNAME rewriting and two-pass cache processing from
worker cache replies and the timed serve-expired callback. Cached ordinary
CNAME integrity checks, tomsg checks, DNSSEC security checks, CD handling,
message/rrset locks, EDE handling, reply encoding and expired-answer accounting
remain. Complete ordinary CNAME chains are still served from cache.
Removed the unused policy TCP-required field; ordinary DNS truncation and TCP
fallback remain. Removed orphaned cfg_region_strlist_copy, dname_has_label,
RPZ network-address decoders, and the now-unused authority-zone-delete argument.
Shared local-zone actions, local data helpers, ACLs and configuration tags remain.

Added direct includes to msgreply.c and outside_network.c for shared types
previously made available indirectly through RPZ headers. Shared TLS code,
certificate validation and remote-control TLS authentication are unchanged.
Existing configuration and service directories are unchanged.

VERIFICATION

RPZ-only stage: all four utilities compiled; 18 forwarding regression groups
and 9 provider regression groups passed. The RPZ stage retained response-IP.
Final stage: all four utilities compiled; 20 forwarding regression groups passed.
Final provider suite: 9 groups passed.
Infrastructure provider-health/backoff/hysteresis/lease/allocation-failure unit
executable passed against the final library.
All 24 modified, retained C files passed syntax checks with
-Werror=misleading-indentation. Source/build-reference audits and git diff
--check pass. nm finds no rpz/respip symbols or the removed orphan helpers in
the final daemon/shared library. Existing compiler const-discard and generated
flex macro warnings remain; no unresolved compile failures.

Added regressions cover CNAME-only upstream responses requiring iterator
restarts, cached intermediate aliases after flushing the terminal answer,
direct CNAME UDP/TCP queries, complete timed serve-expired CNAME responses,
retained authority-zone records and zonefile reloads, authority-zone preservation
through fast_reload, removed directives/module/control-command rejection and
absence of removed statistics. The fixture retries a TCP/UDP port reservation
collision and reports the daemon exit status if startup fails.

Retained coverage includes local A/CNAME/PTR, LAN ACLs, UDP/TCP and pipelining,
positive/negative cache hits, cache administration, EDNS, upstream truncation
and TCP fallback, DNSSEC AD/bogus/CD, prefetch, immediate serve-expired, runtime
forwarding changes, reload/fast_reload, outbound TLS hostname/CA validation,
and mutual-TLS remote administration. Provider tests cover strict priority,
healthy peers, transport failure, silent timeouts, idle recovery, valid negative
and DNSSEC-failure responses, all-provider outages, runtime overrides, TLS
failover, certificate rejection and no plaintext/recursive fallback.

Tests use controlled loopback servers and DNSSEC/TLS fixtures. No live public
provider interoperability, RFC5011 rollover/bootstrap, deployed chroot/privilege
dropping, native service installation, buildworld or buildkernel was run. Host is
Linux; native HalfBSD build/install verification remains required. Existing
security mechanisms were preserved, not newly certified by these tests.

A startup regression caught an inadvertently removed adjacent module setup call;
it was restored before successful final testing. The new authority fixture must
have a transparent local-zone beneath reserved .test to reach its authority data.
These issues were corrected, not accepted as residual failures.

REMAINING FUNCTIONALITY AND FUTURE CAPSICUM

Authority zones/transfers/ZONEMD, stub-zone configuration and shared recursive
internals remain. Optional IPsec/ipset and other previously deferred machinery
remain. Local-zone actions and ACL/tag infrastructure still serve retained
local DNS and access controls and were not removed as response-IP policy.
Compiled Cloudflare -> Google -> OpenDNS priority and no-recursive-fallback
behavior from the preceding commit remain. Configuration directories have not
been reorganized, and no Capsicum implementation has been added.

Future sandbox design still needs configuration/include/CA/control-key reads on
reload, log reopening, PID/control socket lifecycle, worker command channels,
outgoing UDP/TCP/TLS sockets, trust-anchor temporary writes and atomic root.key
replacement, anchor DNS/HTTPS bootstrap, and retained authority-zone files and
transfers. RPZ policy zone mirrors and response-IP reload trees no longer need
sandbox consideration. Runtime behavior of retained operations is unchanged.
