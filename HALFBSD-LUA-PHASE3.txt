IMPLEMENTED

1. A declarative boot policy compiles into the existing Phase II registry and
   scheduler. No second scheduler, event loop, process library or daemon exists.
   Policies select system initialization or an existing logged-in user desktop.
   Concrete tasks remain protected unless --activate-system is explicitly used
   with a configuration. Check/graph/dry-run/shadow perform no startup actions.
   Shadow adds kernel mount and relevant external-process snapshots to rc flag
   comparisons, without adopting or signaling those processes.

2. Bounded native inventories: libc fstab, FreeBSD kernel mounts/processes,
   IPv4 default routes, interface link type/carrier and terminal ownership.
   Native interface-up preserves existing ioctl flags. New connected IPv4 UDP
   and retained asynchronous TCP probes use managed, close-on-exec descriptors.

3. Storage bootstraps before opening runtime control, lock, state and file logs,
   using the SAME supervisor instance. Early logs go to the console. Nested
   local mounts depend on parents; independent mounts retain parallel startup.
   Fstab excludes root/swap/ZFS/noauto; native UFS/tmpfs/devfs/nullfs/cd9660/FAT
   are supported. UFS/FAT preen only runs for unmounted requested filesystems.
   Mounted sources elsewhere are refused. The kernel root is not duplicated;
   read-only root update requires an explicit policy grant.

4. Only local mounts created by this manager are tracked for unmount. Existing
   mounts are never adopted. Reverse cleanup is deferred until child cleanup,
   control/event descriptors, the lock and logs close. Failed native actions
   also receive cleanup. Changed mount ownership or unmount errors are reported;
   no forced unmount occurs. Failed cleanup blocks unsafe reuse of that service
   during this manager session. ZFS uses direct zfs mount -a for already imported
   pools, with no inferred unmount/export ownership.

5. Interface discovery chooses one Ethernet interface, preferring carrier and
   stable name order, or uses explicitly configured interfaces. Foreground
   dhclient owns address/routing changes. Readiness requires IPv4 address plus
   a default route on the primary selected interface. Existing HalfBSD DHCP DNS
   suppression and compiled Cloudflare -> Google -> OpenDNS remain untouched.

6. IPFW verification checks enabled kernel hooks, immutable set 31 guard 65534
   and default deny. Explicit load accepts only a single empty deny baseline,
   installs the immutable guard first, then the established workstation/closed/
   open policy through direct ipfw invocations. There is no flush or rc-script
   invocation. Workstation retains any-source SSH TCP22 and DNS UDP/TCP53, as
   previously requested. Rule readback accounts for ipfw's :default state names;
   unexpected/mismatched/disabled rules fail before network services start.
   Native packet-policy verification is NOT claimed from these source tests.

7. Unbound uses the actual retained local-unbound utility names, idempotent
   trust-anchor initialization as unbound, configuration checking, foreground
   service supervision and matching localhost UDP answer plus TCP readiness.
   Existing trust anchors are retained. Automatic maintenance remains inside
   Unbound. SSH key generation/checking precedes foreground sshd; TCP readiness
   is separate from execution. NTP foreground execution is not clock-sync proof.
   Seatd is opt-in. Existing rc-managed daemons cause preflight refusal rather
   than being adopted, killed or duplicated. Kernel process inventory is checked
   in the manager's own jail; the manager excludes its own PID and owned children.

8. Desktop uses an existing non-root foreground login terminal, private owned
   XDG runtime directory and existing seat service. TOSTOP terminals are refused
   so background manager console logging cannot suspend it. The process library hands
   the terminal to a live owned group under its existing reaper lock and sends
   SIGCONT through the process descriptor, covering early SIGTTIN suspension.
   Reaped handles fail with ESRCH. Exit/shutdown restores the manager's own live
   group. Sway readiness defaults to runtime/wayland-0; niri requires an explicit
   Wayland readiness socket. A stale existing readiness socket is refused.
   An optional system desktop target waits for the configured user's manager
   to report a READY compositor; it does not take ownership of that manager.

9. Boot policy changes require a new manager session; transactional service
   reload and ordinary runtime control continue through the existing engine.
   Installed examples are world-managed; administrator configuration is not.

ASYNCHRONOUS READINESS CORRECTION

After a reported full rebuild and installation, the administrator's root test
identified the hidden failure as the UDP/TCP readiness deadline. Source review
found a defect in OUR NEW Phase III TCP readiness helper, not a FreeBSD defect:
connect() could return EINPROGRESS, but the helper polled immediately and closed
that socket. Later timer callbacks started new handshakes instead of retaining
the in-flight one. Linux's fast loopback completion had concealed this defect.

The IPC API now supplies tcp(address, port), returning a managed nonblocking
socket even when connecting, and connected(fd), which checks completion without
closing it. DNS and SSH readiness retain connections across existing kernel-timer
callbacks, release them on success/error/timeout/cancellation, and preserve a
validated UDP answer while TCP completes. SO_ERROR failures are consumed once
and require closing the failed descriptor. No blocking wait or busy loop was
added. The old immediate tcp_probe implementation and its callers were replaced;
no external repository consumers were found. The API manual describes ownership.

The disposable fixture's listener/UDP sockets and accept are now nonblocking:
a queued connection can disappear before accept, so poll readiness must not be
used as a guarantee that a subsequent blocking accept cannot stall. This is a
separate race in our fixture, not established as the cause of Anvil's timeout.

Added regressions force several pending checks on the SAME connection, then
completion; refusal, timeout, cancellation and exactly-once release; and a
single consumed UDP reply retained through delayed TCP readiness. All 16 Phase
III policy groups and the 14 existing Phase II policy groups pass locally.
Strict GCC C17 compilation passes; complete PIE/archive linkage and real Linux
loopback checks are recorded below. Native confirmation of the corrected
readiness path remains pending; the earlier Anvil run did not reach the private
PTY or Phase I/II native gates. Rebuild/install the updated runtime before rerun,
as these native IPC entry points are new.

AGENTS.md now records the general asynchronous-lifetime lesson, delayed-completion
regression requirement, cross-platform loopback limitation and fixture race.
