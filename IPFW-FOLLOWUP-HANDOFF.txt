HalfBSD IPFW follow-up
Date: 2026-10-11
Status: Implemented and tested; included in the user-authorized IPFW follow-up commit. Commit and push authorized on 2026-10-11.

RESULT

The shipped firewall mode is now workstation, rather than open. Per the user's
updated instruction, its default rules allow SSH on TCP 22 and DNS on UDP/TCP 53
from any source to local addresses, with connection state. Other unsolicited
inbound traffic remains denied. Unbound retains no client ACL. These allowances
are not LAN-only: remote sources can reach these ports when routing permits.
SSH authentication and Unbound protocol/resource protections remain intact.

HALFBSD no longer compiles IPFIREWALL_DEFAULT_TO_ACCEPT. The kernel default
rule therefore denies unmatched packets. The ipfw rc service runs after
FILESYSTEMS/sysctl/hostid and before netif, so loopback, outbound state, DHCP,
and necessary ICMP/IPv6 discovery rules are installed before network setup.
The existing netwait/NETWORKING paths still place it before DNS and SSH.

Before flushing, rc.firewall ensures rule 65534 in reserved set 31 denies all
unmatched traffic. Ordinary IPFW flushes preserve this set; the kernel prevents
its disabling. The guard protects reloads and installations still running the
older accepting kernel. Existing identical guards are reused, avoiding rule
accumulation. Kernel implementation reviewed: ipfw_match_range and
manage_sets in sys/netpfil/ipfw/ip_fw_sockopt.c.

A load failure stops the script and does not publish /var/run/ipfw.ready.
The marker is removed at the beginning of every attempt. ipfw status now checks
readiness, the persistent guard, and IPv4/IPv6 hook state. DNS and SSH prestart
functions refuse startup when readiness or firewall status fails. Their own
DNSSEC and administrative/user authentication remain unchanged.

Reload uses the existing flush-and-rebuild implementation, with the persistent
unmatched-packet deny guard. It is not an atomic replacement: traffic may be
briefly denied, and a failed load can leave a partial policy. Partial workstation
rules permit DNS/SSH service traffic, loopback and outbound/bootstrap traffic;
unmatched traffic remains denied. Previously running services
are not killed after a failed reload. Their packets remain subject to IPFW.
An explicitly selected open policy still intentionally permits all traffic.

LAN CONFIGURATION

New rc.conf settings:
  firewall_trusted_interface=""
  firewall_trusted_networks=""

Both defaults are empty: workstation allows DNS and SSH from any source without
an interface restriction. The administrator can optionally restrict these two
services by setting BOTH an incoming interface and space-separated IPv4 networks.
Doing so replaces the default any-source service rules. Example ONLY (replace
with the actual LAN, not installed defaults):
  firewall_mode="workstation"
  firewall_trusted_interface="em1"
  firewall_trusted_networks="192.168.50.0/24"

With those optional settings, workstation permits UDP 53 and TCP 22/53 only from
those networks on that interface. The same settings control DNS and SSH network
reachability. Other inbound ports remain denied. Interface tokens and network
characters are checked; IPFW validates the actual network syntax. Setting only
one of the two restriction settings is rejected. Closed mode remains loopback
only; open mode intentionally allows all traffic.

Existing explicit firewall_mode="open" in /etc/rc.conf remains an administrator
override; changing the shipped defaults does not override it. Existing explicit
Unbound bindings also remain unchanged. Upgrade configuration and kernel together
and inspect the installed policy. Use console access when changing the policy:
the default rules permit remote SSH and DNS; optional LAN restrictions or closed
mode can block remote SSH if configured incorrectly. No firewall was changed on this
Linux host and no live remote connection was interrupted by this task.

NATIVE ACCEPTANCE STILL REQUIRED

Build/install the HALFBSD kernel and world; inspect effective /etc/rc.conf and
sysctl settings. At a local console, verify:
  sysctl net.inet.ip.fw.enable net.inet6.ip6.fw.enable
  ipfw -S list
  ipfw -a list
  service ipfw status
Check guard 65534 set 31 and kernel deny rule 65535. Confirm loopback DNS,
DHCP addresses/routes, outbound DNS UDP/TCP/TLS, UDP/TCP DNS and SSH from a
client without LAN settings. Verify other unsolicited ports remain blocked.
With optional LAN restrictions configured, verify trusted clients succeed and
untrusted clients cannot reach DNS/SSH. Test reload and reboot.
Inject policy-load failure only in a controlled console/test environment; verify
unmatched traffic stays denied, readiness disappears, and DNS/SSH startup is
refused. Confirm actual native rcorder and packet behavior, including IPv6.

Administrator disabling hooks or deleting the reserved guard deliberately can
change protection. rc status detects missing guard/disabled hooks at startup,
not continuously. Custom rules in reserved set 31 survive flushes as before and
must be included in any installed-policy audit. Old kernels remain accepting
before their first successful guard installation; rebuild/boot the new kernel
for deny-from-boot behavior. A failed early firewall setup may prevent DHCP and
networking, deliberately failing closed rather than exposing services.
