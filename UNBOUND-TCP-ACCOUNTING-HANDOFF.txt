Branch: halfbsd2
Baseline: 738a9c5be4ce
Status: Implemented and tested on Linux; included in the user-authorized TCP accounting fix commit. Commit and push authorized on 2026-10-11.

CONFIRMED ROOT CAUSE

comm_point_perform_accept incremented a matching tcl_addr counter and stored
its pointer on the listening comm_point. The accepted child kept NULL, so
comm_point_close(child) could not release its quota. A rejected accept also
left a non-owned entry on the listener, risking an incorrect decrement during
listener destruction. This is the pre-existing fourth-pass finding, reproduced
before modifying production code: the first TCP DNS query from 127.0.0.5 worked,
but another query after close failed with ConnectionResetError for the entire
bounded cleanup wait. Evidence: /tmp/unbound-tcp-limits-before.log.

OWNERSHIP AND FIX

Quota lookup/acquisition now occurs in the TCP accept callback after accept
succeeds, and stores the entry on the accepted handler only after acquiring
quota. The listener owns no connection count. A rejected accept closes the new
socket without storing a quota pointer. Event allocation precedes accept and
therefore acquires no quota on failure.

comm_point_close releases the count and immediately clears the pointer. Repeated
close/delete/reclamation is safe and does not decrement another connection's
count. If registering the accepted handler's event fails, the existing reclaim
path closes it, releases quota, and returns it to the handler pool immediately.

Read EOF/errors, write errors, peer resets, timeout, dropped replies, and listener
or worker destruction already converge on reclamation/comm_point_close. Those
paths now have the correct quota entry. No alternative cleanup framework was
added. tcl_new_connection/tcl_close_connection already provide locked accounting;
tcp_conn_limit.c needed no changes.

The pointer borrows memory from the tcl_list region; the child owns one count,
not the entry allocation. Ordinary reload/shutdown destroys worker listeners
and children before resetting/freeing that region. Fast reload retains the old
region in its construction structure until changes and worker acknowledgments
complete, so old references can be released before that region is destroyed.

RELATED FAST-RELOAD ACCOUNTING

The former fast-reload path cleared active handlers' quota pointers without
counting them in the replacement tree. It also missed newly added limits when
the old tree was empty. The replacement now releases old counts and rebinds/
counts every active handler in the new tree while ALL workers are paused, before
ANY worker resumes accepting. Newly limited connections are included. Lowering
a limit retains existing connections and their true count; new accepts remain
blocked until active occupancy drops below the new limit. Removing limits clears
old references and leaves clients unrestricted.

If either the old or replacement tree contains limits, fast_reload +p uses the
existing synchronized pause mechanism. A nopause tree swap cannot safely rebind
live accounting pointers while accepts/closes proceed. No new option or connection
implementation was introduced; nopause behavior without limits is unchanged.

SCOPE AND NEXT STEP

No remaining quota-accounting failure was observed in these tests. Tested
ownership/error paths are now balanced; no claim is made of exhaustive coverage
of every OS-specific failure or event backend. Tests used the built-in mini-event
backend on Linux, not native HalfBSD, libevent, or a deployed chroot/UID setup.

The DNS provider hierarchy, iterator, forwarding/caching/DNSSEC algorithms,
configuration paths, IPFW, SSH, removed ACL subsystem, and Capsicum code are
unchanged. Existing DNS/TLS/control suites pass. No source-reduction pass or new
configuration directives are part of this fix.
