### B14. Retire FreeBSD compatibility older than FreeBSD 11 and remove a.out support

**Purpose and locations:** HalfBSD should retain binary compatibility only as far back as the **FreeBSD 11 ABI**. Remove compatibility machinery whose sole purpose is supporting FreeBSD 10 and earlier, together with obsolete a.out executable support. Relevant areas include historical `COMPAT_FREEBSD*` kernel options and implementations, compatibility syscall code, associated libc/libsys compatibility glue, `sys/modules/aout`, executable-format handlers, build/configuration integration, tests, documentation, and installed-file metadata.

The original audit identifies ancient FreeBSD ABI tiers and a.out as candidates for retirement, while warning that newer compatibility entry points, symbol versions, and syscall numbering must be preserved where still required. HALFBSD-ARCHITECTURAL-AUDIT

**HalfBSD compatibility policy:** Define the native FreeBSD ABI compatibility floor as:

```text
KEEP:
    COMPAT_FREEBSD11
    COMPAT_FREEBSD12
    COMPAT_FREEBSD13
    COMPAT_FREEBSD14
    COMPAT_FREEBSD15
    and any newer applicable compatibility tiers

REMOVE:
    COMPAT_FREEBSD10
    COMPAT_FREEBSD9
    COMPAT_FREEBSD8
    COMPAT_FREEBSD7
    COMPAT_FREEBSD6
    COMPAT_FREEBSD5
    COMPAT_FREEBSD4
    and any still-older native FreeBSD compatibility tiers
```

`COMPAT_FREEBSD11` is explicitly protected. Do not remove, weaken, or silently fold it into another tier.

### Removal rule

Remove implementation only when it is **exclusively required for FreeBSD 10 or earlier compatibility**.

Do not remove code merely because:

- it originated in an old compatibility tier;
- its symbol/version name contains an older FreeBSD release number;
- it resides in a compatibility directory;
- it is shared by both retired and retained ABI tiers.

Before deleting anything, trace whether the code is used by `COMPAT_FREEBSD11` or newer compatibility support.

### Pre-removal audit requirement

Before modifying the tree, produce a table for every remaining native `COMPAT_FREEBSD*` tier containing:

- option/tier name;
- FreeBSD ABI generation supported;
- kernel source files and syscall implementations involved;
- libc/libsys symbols associated with the tier;
- shared helpers used by other compatibility generations;
- whether current retained software depends on it;
- whether the code is exclusive to FreeBSD 10 or earlier;
- proposed disposition.

Do not begin deleting ABI-sensitive implementation until the dependency boundary between `COMPAT_FREEBSD10` and `COMPAT_FREEBSD11` is clear.

### Preserve syscall numbering

Removing an old syscall implementation does **not** authorize syscall renumbering.

If an obsolete syscall occupies a historical slot, leave the slot reserved or otherwise preserve the numerical ABI as appropriate.

For example:

```text
before:

syscall 100    obsolete FreeBSD-10 interface
syscall 101    obsolete FreeBSD-10 interface
syscall 102    retained interface
```

may become:

```text
after:

syscall 100    obsolete/reserved
syscall 101    obsolete/reserved
syscall 102    retained interface
```

but must **not** become:

```text
syscall 100    retained interface
```

The original audit explicitly requires retaining syscall slots rather than renumbering interfaces. HALFBSD-ARCHITECTURAL-AUDIT

### Preserve current libc/libsys ABI

Do not delete an exported libc or libsys symbol merely because its version label or implementation ancestry predates FreeBSD 11.

Before removing any compatibility symbol or implementation:

- compare current libc and libsys symbol maps;
- identify whether contemporary base or package binaries still reference it;
- preserve symbols required by the retained current ABI;
- preserve compatibility symbols required by `COMPAT_FREEBSD11` or newer.

The goal is to stop supporting **FreeBSD 10-and-earlier binaries**, not to break current software.

### a.out executable support

Audit and remove obsolete native a.out executable support where no retained component requires it.

Candidates include:

- `sys/modules/aout`;
- a.out kernel executable handlers;
- a.out-specific configuration and build integration;
- headers and tools used exclusively by native a.out execution;
- tests, documentation, and installed-file entries used only for a.out.

Preserve all ELF infrastructure.

Do not confuse obsolete a.out execution with generic object-format support needed by:

- ELF executables;
- kernel modules;
- compiler/linker tools;
- EFI;
- boot loaders;
- debuggers;
- core dumps;
- cross-development.

HalfBSD remains an ELF system.

### Explicitly protected functionality

B14 provides **no authorization** to remove or alter:

- `COMPAT_FREEBSD11`;
- any newer `COMPAT_FREEBSD*` tier;
- current amd64 ELF execution;
- current libc/libsys ABI;
- current package compatibility;
- retained syscall numbering;
- ELF kernel-module loading;
- debugger/core-file handling;
- DTrace, `ktrace`, `truss`, `procstat`, or related diagnostics;
- compiler/linker/toolchain infrastructure;
- bhyve host functionality;
- EFI/bootloader object handling;
- FreeBSD32/IA32 compatibility;
- Linux compatibility;
- Linux32 compatibility;
- cross-compilation support.

FreeBSD32 and Linux compatibility are separate architectural decisions and must not be inferred from the native FreeBSD ABI cutoff. The original audit explicitly distinguishes native amd64 compatibility from FreeBSD32. HALFBSD-ARCHITECTURAL-AUDIT

### Shared compatibility code

If FreeBSD 10-or-earlier support and FreeBSD 11+ support share implementation:

- retain the shared implementation;
- remove only the older dispatch/entry points where possible;
- refactor shared code only when doing so clearly reduces complexity without changing retained ABI behavior.

Do not duplicate retained code merely to make the source-tree boundary cosmetically cleaner.

### Current-package validation

Treat FreeBSD 11 as HalfBSD’s explicit minimum compatibility floor.

Before committing the removal:

- verify that retained current base programs build and run;
- verify representative contemporary packages;
- verify Firefox/Gecko or any other software currently establishing the need for `COMPAT_FREEBSD11`;
- confirm no intended current package requires `COMPAT_FREEBSD10` or earlier.

If a current retained package demonstrably requires an older compatibility tier, report that dependency before removal rather than overriding the policy silently.

### Disposition and expected result

The intended state is:

```text
HalfBSD compatibility floor
===========================

FreeBSD 11 ABI    KEEP
FreeBSD 12 ABI    KEEP
FreeBSD 13 ABI    KEEP
FreeBSD 14 ABI    KEEP
FreeBSD 15 ABI    KEEP

FreeBSD 10 ABI    REMOVE
FreeBSD 9 ABI     REMOVE
FreeBSD 8 ABI     REMOVE
FreeBSD 7 ABI     REMOVE
FreeBSD 6 ABI     REMOVE
FreeBSD 5 ABI     REMOVE
FreeBSD 4 ABI     REMOVE
older tiers       REMOVE

native a.out      REMOVE
modern ELF        KEEP
```

A binary requiring FreeBSD 10 or earlier compatibility may cease to execute on HalfBSD. Rebuilding such software against the current HalfBSD ABI is the intended migration path.

### Benefit / risk / confidence

This creates a clear, testable ABI policy rather than an indefinite accumulation of historical compatibility.

Expected benefits include:

- fewer historical syscall implementations;
- fewer compatibility code paths;
- less executable-format machinery;
- simpler build/configuration options;
- clearer supported binary-compatibility expectations.

Risk is low-to-moderate for code proven exclusive to FreeBSD 10 and earlier, but potentially high where compatibility implementations or exported symbols are shared with FreeBSD 11+.

Confidence should therefore be assigned **per implementation boundary**, not merely per `COMPAT_FREEBSD*` option name.

### Validation

After removal, perform at minimum:

- clean world build;
- clean kernel build;
- all retained module builds;
- staged installation;
- libc exported-symbol comparison;
- libsys exported-symbol comparison;
- syscall-number comparison confirming no retained syscall moved;
- representative current base binaries;
- representative contemporary packages;
- Firefox/Gecko build and execution;
- compiler and linker operation;
- debugger operation;
- core-dump generation and inspection;
- `ktrace`, `truss`, and `procstat` smoke tests;
- bhyve host operation;
- EFI/bootloader builds;
- external kernel-module builds;
- confirmation that `COMPAT_FREEBSD11` remains functional;
- confirmation that `COMPAT_FREEBSD10` and older build options/implementation are gone;
- confirmation that native a.out execution support is absent.

**Core rule:** HalfBSD supports native FreeBSD binary compatibility back to **FreeBSD 11, and no further**. Remove FreeBSD 10-and-earlier compatibility and a.out support without weakening the retained FreeBSD 11+ ABI.
