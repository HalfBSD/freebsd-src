The small singleboot.lua task path uses existing halfbsd.os/proc APIs, direct
argv execution and bounded synchronous waits. This is not another scheduler,
process supervisor or shell-command layer. Steps printed as BEGIN/OK/FAILED:
1. Confirm root directly launched by PID 1, notification descriptor 3.
2. Verify the already kernel-mounted ZFS root and devfs, report root read-only
   state and console availability. Do not remount root writable automatically.
3. Run /sbin/zfs mount -a for already-imported pools; list mounted ZFS datasets.
   No imports, encryption/key setup, fstab mounts, swap or destructive repairs.
4. Run /sbin/kldload -n -v amdgpu, then /sbin/kldstat -n amdgpu.ko.
   This preserves already-loaded modules and shows native module/kernel output.
5. List DRM card/render nodes and require a card node. Module load plus a DRM
   node is only bring-up evidence: it does not prove acceleration, compositor
   correctness or which driver owns every node. Inspect native kernel output.
6. Send SINGLE, close notification and exit normally. PID 1 requires both the
   exact token and successful exit before publishing single-ready and opening
   its existing single-user shell. PID 1 retains console ownership/password
   policy, alternate-shell prompt, signals, reaping and reboot responsibilities.

ZFS and kldload each have a 120-second proc.run deadline; kldstat has ten seconds,
with bounded exec/termination handling. PID 1 prints elapsed waiting progress
every five seconds, with the existing 600-second outer startup bound. A kernel
hang/uninterruptible driver operation cannot be guaranteed recoverable by these
userspace timers. A graphics modeset may temporarily blank the physical display.
Failures print reasons, send FAIL when possible, publish boot_result=failed and
enter PID 1 recovery; they never start RC over partial Lua changes.

No DHCP, IPFW policy setup, DNS, SSH, NTP, syslog, ldconfig, getty, desktop,
configuration reload server or service manager socket is started. Kernel IPFW
retains its existing built-in policy. Loaded AMDGPU and ZFS mounts remain for
inspection; kernel/PID 1 handle final reboot. No new logging daemon or persistent
boot-log file is required. Output goes to the physical console as it happens;
full multiuser service transitions also now have plain console progress.

At the shell, exiting/Ctrl-D restarts single-user handling without rerunning
initialization or continuing to multiuser. The default-stage change deliberately

HISTORICAL PHASE IV MULTIUSER IMPLEMENTATION (SUPERSEDED AS DEFAULT)

ARCHITECTURE AND MODE SELECTION

The existing C /sbin/init remains PID 1. Lua is now the default. The selector
requires no marker and no loader opt-in. halfbsd.boot_mode=rc explicitly selects
traditional RC recovery; lua explicitly selects Lua. Invalid overrides enter
single-user recovery. The obsolete /etc/halfbsd/lua-boot marker is not read.
Loader init_exec/init_script/init_chroot are honored only when RC is selected,
preventing a second startup path in ordinary Lua mode.

PID 1 starts /usr/sbin/halfinit with /etc/halfbsd/system.lua, --activate-system
and an internal descriptor-3 channel. Configuration and included definitions
must have root-owned, non-group/world-writable path components. The existing
Lua registry, scheduler, supervisor, process descriptors and kqueue remain;
there is no second reaper, dependency engine or supervisor daemon.

The manager bootstraps storage before lock/control/state/log initialization.
It sends READY exactly once after devices, runtime, loopback, firewall, control
and the COMPLETE selected multiuser/desktop/gateway target are ready. Configured
swap is a hard dependency, not an optional target member. PID 1 waits at most 600 seconds for that handoff, retains
its supervisor child, and then proceeds to its existing console/getty handling.
The supervisor has its own session without a controlling terminal, null input
and console output opened O_NOCTTY. Native file opens also use O_NOCTTY. The
example retains lifecycle logs under /var/run/halfbsd/boot.log. The final shutdown
record reopens /dev/console because login can revoke old console descriptors.
Required DHCP/network/DNS/SSH/NTP initialization failure now refuses multiuser
readiness and enters single-user recovery. NTP process readiness still does not
claim clock synchronization. Ordinary console login is started only after the
complete selected target; recovery retains PID 1 single-user console handling.

The default /etc/rc.console tty entry is mapped to native authenticated login
in Lua mode, retaining existing controlling-terminal initialization. RC mode
is untouched. Automatic login and PAM/session orchestration are deliberately
not added; that remains the previously discussed future option. Optional
non-root desktop execution continues to use the Phase III existing-user-session
model, not a compositor run by the root system manager.

halfbsd.boot_active records the actual selected startup mode for reboot(8).
Unexpected manager exit is recognized before getty child handling and enters
controlled single-user recovery. Lua startup/shutdown never executes /etc/rc,
rc.shutdown, rc.final or the rc.console helper. Partial Lua initialization does
not automatically fall back to RC. A failed attempt latches recovery; changing
startup systems after an attempt requires a full reboot.

SHUTDOWN

Normal shutdown(8) already signals PID 1. In active Lua mode, ordinary reboot
and halt now request the corresponding existing PID 1 transition instead of
stopping init and killing the manager before it can orchestrate cleanup.
Reboot, halt, poweroff and powercycle signals retain native PID 1 handling.
Explicit reboot -q remains an emergency bypass. Advanced reboot flags and live
reroot are not supported through the initial orderly Lua path; advanced flags
require explicit quick reboot and reroot requests are refused into recovery.

PID 1 sends TERM/CONT to its retained supervisor and waits up to 120 seconds,
then KILL with a five-second reap bound. The manager refuses new control
mutations/reloads, uses its existing bounded reverse-dependency stop sequence,
reaps owned children, releases only its own mount/swap resources and calls sync.
PID 1 retains its existing remaining-process cleanup, final sync and kernel
reboot duties. RC shutdown and Lua shutdown are mutually exclusive. A shutdown
failure is logged, not silently described as clean. Descendants escaping the
owned foreground-process/group model remain a known limitation; the native
PID 1 remaining-process cleanup is still necessary.

SUPPORTED INITIAL BOOT CONFIGURATION / RC RESPONSIBILITY AUDIT

Initial integrated boot requires an already kernel-mounted ZFS root with /usr,
manager, modules, interpreter and libraries accessible before additional mounts.
Separate /usr and non-ZFS integrated roots are outside this initial scope;
choose RC for those layouts. This restriction does not remove Phase III's
ordinary userspace local-filesystem support.

Devices: init's existing devfs mount is retained and verified. Essential
/dev/null and /dev/console must exist. Optional explicit device_rules change
mode/owner only on real device entries. Arbitrary rc devfs rulesets, kld loading,
legacy device discovery, encrypted disks and custom devd behavior are not copied.
Kernel-supported Ethernet/IPFW and already accessible storage are prerequisites.

Storage: explicit read-only root update; existing local fstab filtering and
UFS/FAT preen (only unmounted supported entries); zfs mount -a for already
imported pools. No automatic pool imports, key loading, destructive repair,
exports, remote filesystem boot or guessed ownership. New /tmp and /var/tmp
preparation uses 1777; /var/run uses 0755. Existing content is not blanket-deleted.

Swap: false, fstab (default, excluding noauto), or explicit existing /dev paths.
Native swapon/swapoff wrappers preserve errno. EBUSY is treated as already active
and not owned. Only successfully activated devices receive cleanup; changed
device identity refuses cleanup. External root swapoff/re-swapon of the same
unchanged device cannot be distinguished and must not race this manager. No encrypted
swap attachment, file-backed swap, automatic device creation or forced swapoff.

Hostname: optional explicit native hostname initialization. Kernel/loader root
and devfs work are not duplicated. RC hostid/entropy-save/pool-import policies,
extra kernel-module requirements and site-specific RC tasks are not inferred;
a VM image must have its required kernel storage/network/firewall support and
existing identity/configuration prepared. Broader hardware/host coverage remains
outside the documented initial supported configuration.

Network: existing Ethernet discovery/direct foreground dhclient and route
readiness. One-second event timers monitor loss of address/default route and
recover the network readiness service when both return, honoring operator holds
and shutdown state. Dependents follow the existing supervisor's degradation
policy. DHCP's existing dhclient-script remains an executable implementation
helper; it does not source rc.subr. Administrator DHCP hooks require review.
This is not a rewrite of DHCP and does not adopt another client's processes.
DHCP DNS suppression and the compiled Cloudflare -> Google -> OpenDNS hierarchy
are unchanged. No automatic NAT or gateway selection is introduced.

IPFW: existing Phase III load/verify behavior remains. Loading requires the
empty immutable default deny baseline, installs the guard before selected rules,
verifies enabled kernel hooks and readback, and never flushes. Firewall failure
prevents network services and the READY handoff. Workstation policy retains the
previously requested ANY-SOURCE SSH/DNS permits; do not describe it as LAN-only.
Open/closed policies remain explicit. Native packet tests are pending.

Services: existing Unbound validation/anchor/foreground DNS readiness, SSH keys
and foreground TCP readiness, NTP foreground supervision and optional seatd
remain. Configuration/provider hierarchy unchanged. An NTP exec is not clock
synchronization. A DNS TCP handshake is not full DNS-over-TCP response validation.
