### A12. Obsolete interactive Unix conveniences and non-system application utilities

**Purpose and locations:** Audit and remove historical terminal conveniences, obsolete interactive-user facilities, and application-layer utilities that do not belong in HalfBSD's minimal workstation base.

Strong candidates include:

- `usr.bin/enigma`
- `usr.bin/leave`
- `usr.bin/banner`
- `usr.bin/biff`
- `usr.bin/msgs`
- `usr.bin/talk`
- `usr.bin/write`
- `usr.bin/mesg`
- `usr.bin/lock`
- `usr.bin/look`
- `usr.bin/asa`
- `usr.bin/ul`

Also remove the remaining historical `MK_GAMES` utilities, including where present:

- `caesar`
- `factor`
- `fortune`
- `grdc`
- `morse`
- `number`
- `pom`
- `primes`
- `random`

Some or many of these utilities may already have been removed, disabled, or orphaned by earlier HalfBSD excision passes. Treat this list as an audit target rather than an assertion that every named program still exists. For each item, determine whether its source, build integration, manpages, tests, supporting data files, configuration hooks, or related daemons remain anywhere in the tree.

**FreeBSD rationale / HalfBSD fit:** These programs primarily reflect the historical model of a multi-user interactive Unix system in which users logged into terminals, exchanged messages through TTYs, received local mail notifications, consumed system bulletins, locked terminals, printed text to line printers, or used small recreational/application utilities supplied directly by the base OS.

That model does not match HalfBSD's intended role as a modern workstation and development platform. Functionality such as graphical session locking, messaging, reminders, text processing, recreational utilities, unit conversion, and similar conveniences should generally live in packages or user applications rather than the operating-system base.

Several candidates are particularly poor fits:

- `biff`, `msgs`, `talk`, `write`, and `mesg` belong to the traditional shared-terminal and local-login environment.
- `enigma` provides obsolete encryption and should not be presented as a modern security facility.
- `leave` is a shell-session reminder utility.
- `banner` and `asa` primarily serve historical printing workflows.
- `ul` primarily supports historical terminal overstriking/underlining conventions.
- `lock` implements terminal locking rather than modern graphical session locking.
- The `MK_GAMES` collection consists of recreational or standalone application utilities rather than essential operating-system functionality.

**Dependencies:** These should generally be leaf userland programs, but do not assume that because a binary has already disappeared all of its integration disappeared with it.

For each candidate:

1. Determine whether the program still exists in the current HalfBSD tree.
2. If already removed, search for residual build entries, `MK_*` options, manpages, tests, data files, periodic hooks, rc references, aliases, documentation, or other dangling references.
3. If still present, identify reverse dependencies before deletion.
4. Remove only supporting infrastructure that exists solely for the removed utility or utility group.

In particular, removal of `talk`, `write`, `mesg`, `biff`, or `msgs` should include an audit for any remaining daemon-side or inetd-era integration associated exclusively with those facilities.

**Disposition and impact:** Remove any remaining listed utilities and their dedicated build integration, documentation, tests, data files, and configuration support.

Where an item was already removed in an earlier pass, complete the cleanup by deleting any orphaned references or now-unused build options rather than attempting to remove it again.

Do not broaden this item into removal of generally useful shell, scripting, diagnostic, or text-processing utilities merely because they are old. Age alone is not the criterion. The criterion is whether the functionality belongs in HalfBSD's operating-system base and whether it serves the workstation, development, administration, VM, networking, or recovery model.

**Benefit / risk / confidence:** Individually these are small removals, but collectively they reduce historical userland clutter, obsolete interfaces, unnecessary documentation, build switches, and application-layer functionality in base. Expected runtime impact is negligible. Risk is low for the explicitly listed utilities, assuming reverse-dependency checks are performed. Confidence is high.

**Validation:** Build and install world; verify that no remaining source-tree, build-system, manpage, test, configuration, or documentation references point to removed binaries. Confirm that retained shell, console, SSH, terminal, package-management, development, and administrative workflows continue to function normally.
