HALFBSD UNBOUND: FOURTH PASS — DNS CLIENT ACL REMOVAL
Date: 2026-10-11
Branch: halfbsd2
Baseline: 30fbbb37ffef, Remove Unbound RPZ and response-IP policy infrastructure
Status: Implemented and tested on Linux. Included in the user-authorized fourth-pass implementation commit; not pushed.

RESULT

Unbound has no source-address or listening-interface authorization stage for
ordinary DNS queries. IPFW is the administrator's network-access authority.
The default DNS listener is IPv4 0.0.0.0:53, UDP and TCP. Explicit bindings
remain supported; no LAN-interface enumeration or discovery service is needed.
IPv6 transport remains available by explicit configuration but defaults to no.
AAAA records remain supported. DNS from 127.0.0.1 continues to work.

IMPORTANT: repository firewall defaults are OPEN. This pass does not establish
that an installed HalfBSD machine blocks untrusted DNS clients. See the IPFW
findings and required corrections below. No firewall, SSH, kernel configuration,
provider hierarchy, directory layout or Capsicum behavior was changed.

PREREQUISITE CHECKPOINT

The tree was clean on halfbsd2 before work. The RPZ/response-IP implementation
was already committed as 30fbbb37ffef and independently tested: all four retained
utilities compiled, 20 forwarding groups and 9 provider groups passed. Latest
reduction results/plan and policy/provider handoffs were reviewed. RPZ and
response-IP implementations were absent; their former ACL dependencies therefore
did not block this pass. No third-pass work was reverted or duplicated.

REMOVED IMPLEMENTATIONS AND INTERFACES

Deleted contrib/unbound/daemon/acl_list.c (745 baseline lines) and acl_list.h
(205 lines): 950 lines in physically deleted implementation/header files.
Removed source-network tables, default localhost permission entries, interface
ACL pointers, proxy/client ACL lookups, query deny/refuse helpers, non-local
authorization, allow_setrd/allow_snoop/allow_cookie admission actions, memory
accounting, initialization, cleanup, reload trees and socket diagnostics.
No unconditional-allow callback or compatibility wrapper replaces them.

Removed configuration fields, lexer/parser tokens and actions, generated
parser/lexer entries, option getters/setters, validation and documentation for:
  access-control
  access-control-tag
  access-control-tag-action
  access-control-tag-data
  interface-action
  interface-tag
  interface-tag-action
  interface-tag-data
Also removed define-tag, local-zone-tag and local-zone-override: their sole
remaining consumers selected DNS content by client/interface/network policy.
access-control-view/interface were already absent and remain rejected.
Removed tag conversion/storage helpers, triple-string/byte-list helpers, tag
reload consistency handling and interface-address/port tree comparison helpers
whose only consumers were the deleted policy subsystem.

Global local-zone types (including deny/refuse response types), manual local
records, ordinary aliases and zone lookup remain. Their content behavior is
independent of client source addresses. Local-zone APIs now take only retained
arguments; libunbound no longer passes empty policy-tag arguments.

Removed the ACL-only unwanted.queries counter and its structures, aggregation,
control output, manual entries and metrics/Munin examples. Unwanted upstream
replies, malformed-request handling, rate-limit counters and ordinary statistics
remain. The bundled statistics layout changes; rebuild control/library consumers
with the daemon. Public libunbound DNS resolution APIs remain unchanged.

There were no dedicated ACL mutation commands in the baseline control registry.
The obsolete configuration names disappear from generic get_option/set_option
administration; regression tests verify rejection. All ordinary forwarding,
cache, local-record, reload, DNSSEC and authenticated control commands remain.

LISTENER AND SECURITY

The existing default listener path binds 0.0.0.0 instead of 127.0.0.1; do-ip6
now defaults to no. Existing port/UDP/TCP defaults remain 53/yes/yes.
Wildcard IPv4 UDP sockets use existing packet-destination ancillary support,
so replies originate from the address queried by the client. The first wildcard
regression exposed wrong-source replies to a secondary local address; this was
corrected without setting interface-automatic or adding interface discovery.
Explicit wildcard bindings use the same packet-destination path.

Packet validation, EDNS, truncation/TCP fallback, DNSSEC and trust-anchor code,
cache integrity/security checks, forwarding retries and provider selection,
rebinding/private-address protections, privilege dropping, chroot and TLS
certificate validation remain. Iterator executable code and provider code are
unchanged; one iterator comment replaces an obsolete allow_snoop reference.

DNS Cookies remain optional under answer-cookie. Client-only cookies bootstrap,
valid cookies are accepted, and invalid supplied server cookies receive a
BADCOOKIE challenge on UDP. Missing cookies do not block queries. Malformed
cookies remain FORMERR. This protocol check applies uniformly, without any
administrator-configured source-network authorization.

Rate limiting was evaluated separately and retained: per-client/domain rates,
valid-cookie rate accounting, TCP connection limits, wait limits, queue/time
limits and resolver capacity prevent resource abuse. They do not decide which
networks are admitted. Their source-address accounting is intentionally retained.
Authority-zone NOTIFY/update authorization also remains; it authorizes state
changes, not ordinary DNS queries. Authority zones/transfers remain future work.

Remote-control TLS authentication/certificate checks and filesystem-protected
Unix control access remain. Wildcard DNS binding does not change control binding
or authorize unauthenticated administration.

CONFIGURATION MIGRATION

Existing local-unbound-setup generates no client ACLs. Its managed-main-file
upgrade path now removes obsolete client/interface/tag/override directives,
including quoted arguments spanning lines, while preserving ordinary quoted
records, includes, TLS transport settings and certificate bundles. Existing
backup/replacement behavior remains. Repeated setup is idempotent.
control.conf/lan-zones.conf generation, directory layout and persistent root.key
location are unchanged. DHCP still supplies addressing/routing, not DNS servers.

Custom include files are not silently rewritten: administrators must remove
obsolete policy entries there before checkconf/restart. The reduced parser
rejects them, rather than accepting no-ops. Explicit custom listen bindings are
preserved; delete an old loopback binding if the administrator wants the new
wildcard default. Fresh generated configuration requires no binding changes.

BASELINE-CONFIRMED TCP LIMIT ISSUE (NOT INTRODUCED OR FIXED HERE)

With tcp-connection-limit: 127.0.0.5/32 1, closing an idle TCP connection does
not release quota as expected: the next connection resets. A direct controlled
comparison reproduces ConnectionResetError in both the committed third-pass
build and the fourth-pass build. netevent.c/tcp_conn_limit.c are unchanged.
Source review indicates the accepted child does not inherit the tcl_addr that
would release the count. This needs a separate TCP-limiter fix and regression.
This pass verifies cap enforcement, unaffected UDP and removing the cap by
reload; it does not claim normal quota release is working.

IPFW AUDIT — SOURCE/MOCK RESULTS, NOT INSTALLED ACTIVE POLICY

1. Compiled in: YES in sys/amd64/conf/HALFBSD; Makefile.inc1 selects HALFBSD as
   the default amd64 kernel. The running installed kernel was not inspected.
2. Active before Unbound: SOURCE ORDERING YES through ipfw -> netwait ->
   local_unbound. Kernel hooks default enabled and rc.firewall enables them.
   Native activation is UNVERIFIED; failed initialization/tunables can break it.
3. Initial deny policy: NO. Kernel IPFIREWALL_DEFAULT_TO_ACCEPT and shipped
   firewall_mode="open" accept traffic. Open mode installs allow-any rule 65000.
4. Initialization before external services: DECLARED ORDER YES. NETWORKING
   depends on ipfw; sshd follows LOGIN/NETWORKING, and local_unbound follows
   netwait. Actual native boot/order/success is UNVERIFIED.
5. Failed initialization stays closed: NO. rc.firewall flushes rules before
   building replacements. Injected failure at rule 3100 aborts before the final
   deny. The compiled fallback accepts non-matching traffic. set -e reports
   failure, but rc.subr run_rc_scripts does not gate later services on success.
6. Trusted-LAN UDP/TCP 53 allowed: NO dedicated trusted-LAN rules. Open mode
   permits every source; workstation/closed modes have no LAN DNS exception.
7. Untrusted UDP/TCP 53 denied by default: NO, default open/fallback accept.
   Workstation denies unsolicited inbound only after successful policy loading.
8. Loopback DNS: rule 100 allows all lo0 traffic in every rendered mode.
   Native IPFW loopback packet flow is UNVERIFIED; Linux resolver flow passes.
9. Outgoing DNS: open permits it; workstation allows outbound TCP/UDP with
   state and check-state replies, covering UDP/TCP DNS and upstream TLS.
   Closed intentionally permits only loopback. Native forwarding is UNVERIFIED.
10. SSH 22: subject to the same IPFW network policy. Open permits all sources;
    workstation has no trusted-LAN SSH exception. SSH authentication is separate
    and unchanged. No native SSH/active-firewall connection testing occurred.

ipfw_status checks hooks and prints the configured mode; it does not prove the
installed rule set is restrictive. IPFW being compiled/enabled is insufficient.
No claim of firewall protection is made from Linux resolver or mocked tests.

SMALLEST NECESSARY FIREWALL FOLLOW-UP (NOT IMPLEMENTED THIS PASS)

Select workstation as the shipped restrictive policy rather than open. Add
administrator-chosen trusted LAN network/interface allowances for UDP/TCP to
local port 53, and apply the same source/interface policy to SSH port 22, with
state for TCP return traffic. No trusted network/interface was invented here.

Ensure a deny rule survives initial setup, flush/reload and every load failure,
using a deny bootstrap/guard or validated staged rules and atomic activation.
To remove the accepting kernel fallback safely, install loopback, DHCP and
necessary outbound bootstrap rules before netif/DHCP; simply changing the kernel
fallback while keeping policy initialization after netif can break networking.
Preserve the existing firewall-first dependency path, and make failed firewall
policy installation prevent external-service startup rather than only log failure.
These corrections belong to a focused firewall change, not a second Unbound ACL.

Native acceptance requires inspecting sysctl hook state and ipfw -a list, testing
boot and injected policy-load failures, then querying DNS over UDP/TCP from both
trusted and untrusted clients. Confirm loopback, outbound DNS/TLS, DHCP/addressing,
gateways and SSH behavior, including after reload. Those tests were not run here.

REMAINING WORK

No retained subsystem prevents complete DNS-client ACL removal. Authority
zones/transfers/NOTIFY/ZONEMD, stubs, shared recursive internals, optional IPsec/
ipset and other deferred code remain. General query/reply log tags and DNSSEC
key tags are unrelated to deleted client-policy tags and remain. Optional EDNS
client-string metadata also remains: it labels upstream queries by client prefix,
but does not authorize clients or choose local-zone policy. It is a candidate
for a later independent reduction. Historical
Changelog and optional patch context are not current accepted configuration.
Configuration-directory migration remains separate. No Capsicum was implemented.
Future Capsicum must account for reload/include/CA/control-key reads, log/PID/
control-socket operations, worker channels, outgoing socket creation, trust-anchor
writes/atomic replacement and retained authority-zone transfers/files. ACL-region
allocation/reload tables no longer need consideration.
