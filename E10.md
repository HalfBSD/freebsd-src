### E10. Obsolete USB device-mode, handheld, and modem-specific support

**Purpose and locations:** Review USB gadget/device-mode implementations, obsolete handheld-device drivers, and modem-specific USB support. Initial candidates include USB gadget/template modules, `cfumass`, `uipaq`, `uvisor`, `urio`, and similarly narrow hardware-specific drivers whose supported devices fall outside HalfBSD’s modern amd64 workstation baseline. The original audit also grouped FireWire here, but **FireWire is explicitly excluded from this removal scope and must be preserved.** HALFBSD-ARCHITECTURAL-AUDIT

**HalfBSD policy:** HalfBSD is a modern amd64 workstation operating system. It should retain broad USB **host** functionality for contemporary peripherals and development work, while removing USB **device-mode/gadget** functionality and narrowly targeted drivers for obsolete handhelds, PDAs, phones, and modems that have no plausible modern workstation use.

A driver is not removable merely because it is old or serial-related. Removal must be based on the exact supported hardware family and whether that hardware belongs within HalfBSD’s supported-device policy.

**Pre-removal audit requirement:** Before modifying the tree, enumerate the exact USB vendor/product IDs and supported hardware families for every proposed removal. For each candidate, report:

- supported device families and USB IDs;
- approximate hardware generation;
- whether the driver is host-side or USB device/gadget-mode infrastructure;
- whether it supports a generic protocol or only particular obsolete products;
- whether any modern development board, USB serial adapter, modem, phone-tethering device, or other plausible workstation peripheral depends on it;
- shared USB, serial, networking, storage, HID, audio, or debugging dependencies;
- reverse dependencies from retained kernel modules and userland tools;
- exact functionality lost if removed.

Present the proposed removal set before deleting hardware-specific support whose modern relevance is uncertain.

**Approved removal targets:**

- USB gadget/device-mode examples and templates that exist to make the HalfBSD machine behave as a USB peripheral rather than as a USB host;
- `cfumass` and associated USB device-mode mass-storage functionality, provided no retained amd64 workstation use depends on it;
- `uipaq`, `uvisor`, `urio`, and similarly obsolete handheld/PDA-specific device families after confirming their exact supported IDs;
- hardware-specific modem drivers whose supported devices are conclusively obsolete and whose removal does not affect generic USB serial or networking functionality;
- source, module/build integration, firmware, configuration, documentation, tests, and installed-file entries belonging exclusively to approved retired device families.

**Explicitly preserve:**

- all ordinary USB host-controller infrastructure;
- USB mass-storage support;
- USB CD/DVD/Blu-ray drives;
- USB keyboards, mice, HID, and input devices;
- USB Audio Class support;
- generic USB serial infrastructure, including `ucom`;
- commonly useful USB serial bridges used for embedded and development work;
- USB networking required for contemporary Ethernet adapters or phone tethering;
- USB debugging and diagnostic infrastructure with retained workstation/development value;
- USB device discovery, hotplug, suspend/resume, and power-management infrastructure;
- shared USB framework code used by any retained device family.

The original audit already identifies USB host infrastructure, `ucom`, common serial bridges, tethering, and useful diagnostics as capabilities that should remain. HALFBSD-ARCHITECTURAL-AUDIT

**FireWire protection:** **Do not remove, disable, simplify, or modify FireWire support as part of E10.** Preserve:

- `sys/dev/firewire`;
- FireWire kernel modules and interfaces;
- `fwcontrol`;
- `dcons` and FireWire-related debugging support;
- FireWire audio/storage/debugging functionality;
- all build, configuration, header, and userland integration required by retained FireWire support.

FireWire may be evaluated separately in a future audit, but E10 provides **no authorization to remove any FireWire functionality**. This is an intentional change from the original E10 grouping, which noted FireWire’s niche audio and debugging uses. HALFBSD-ARCHITECTURAL-AUDIT

**Dependencies:** Preserve shared USB host, `ucom`, tty/serial, CAM/storage, networking, HID/evdev, audio, power-management, and device-event infrastructure unless independently proven unused by all retained functionality. Do not infer that removing one obsolete USB serial device family permits removal of generic serial support.

**Disposition and impact:** Remove only USB gadget/device-mode functionality and narrowly hardware-specific obsolete handheld/modem drivers whose lack of relevance has been demonstrated by device-ID review. Retained USB operation should remain indistinguishable for normal HalfBSD workstation use.

**Benefit / risk / confidence:** Moderate driver and module reduction, primarily eliminating embedded-device-mode functionality and historical peripheral support. Low architectural risk when removal is limited to proven obsolete device families; moderate hardware-coverage risk if device IDs are not audited carefully. High confidence in removing obsolete handheld/gadget leaves; evaluate modem-specific drivers individually.

**Validation:** After removal, test at minimum:

- USB keyboard and mouse;
- USB mass storage;
- USB CD/DVD/Blu-ray;
- USB audio playback and recording;
- common USB serial adapters and development boards;
- phone USB tethering;
- supported USB Ethernet adapters;
- hotplug and device removal;
- suspend/resume;
- retained USB diagnostics;
- **FireWire module build/load and `fwcontrol`/`dcons` preservation checks.**

This version makes E10 much cleaner: **kill gadget-mode and genuinely obsolete USB leaves, preserve the modern USB host stack, and put a bright red “DO NOT TOUCH” fence around FireWire.**
