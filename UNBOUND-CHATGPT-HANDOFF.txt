USER INTENT AND CONSTRAINTS

Reduce bundled Unbound to one reliable workstation/home-network forwarding and
caching resolver. Delete unwanted implementations, directives, documentation,
dependencies, and build references. Do not add feature switches, profiles,
compatibility shims, arbitrary processing-code loaders, or a second implementation.

Keep IPv4 UDP/TCP both ways, multiple forwarders, positive/negative caching,
prefetch, serve-expired, local-zone/local-data including ordinary record types
and PTR, localhost/LAN access controls, DNSSEC validation and automatic anchors,
outgoing DNS-over-TLS with certificate validation, logging/statistics/control,
safe reloads, privilege dropping, and existing chroot support. Preserve shared
TLS required by outgoing DNS and authenticated remote control. Preserve DNS
protocol behavior including EDNS, CNAME chains, truncation and TCP fallback.
Do not rewrite the iterator or introduce Capsicum during this task.

The user narrowed the initial implementation step to an English plan on disk
and easily removable components. The user subsequently explicitly authorized
committing and pushing that completed pass; this has already happened. The latest
request is to write this handoff, not to implement another removal or push it.

COMPLETED REMOVALS

1. DNS64 synthesis: deleted dns64/dns64.c and dns64.h, registration, directives,
   configuration fields/lifetime/control references, allowlists and build rules.
   Removed DNS64's special AAAA message-cache hashing by CD and redundant lookups.
   Ordinary AAAA records and DNSSEC CD behavior remain. NAT64 transport is a
   separate feature and remains, with default 64:ff9b::/96 independent of DNS64.

2. Python query modules and PyUnbound machinery: implementation directories were
   already absent from the import. Removed remaining loader registration,
   configuration support, callback allowlists, build/install rules, Python/SWIG
   dependency probes, and acx_python.m4/ax_pkg_swig.m4.

3. Dynamic-library query modules: deleted dynlibmod implementation, header and
   example, plus loader/configuration/callback/statistics/build/dependency support.

4. Dnstap: deleted its implementation, headers, protobuf schema, frame-streams
   transport and unbound-dnstap-socket source. Removed parser/configuration,
   logging hooks, daemon/worker state, network parameters, callback allowlists,
   fast-reload handling, build/dependency probes, and user documentation.

Updated generated configure, lexer and parser files and HalfBSD library build
references. The portable lexer build rule now uses -Pub_c_, matching HalfBSD.
Removed obsolete downstream patches and Fedora packaging referencing deleted
features. Updated configuration/control manuals and examples. Historical
Changelog/CREDITS entries remain as provenance.

Removed dependency support: Python development libraries, SWIG, the dynamic-module
dlopen probe, libfstrm, protobuf-c and protoc-c. These optional dependencies were
already absent from the baseline executable. OpenSSL, pthread and anchor XML
support remain required. Redis/hiredis support has NOT yet been removed.

utilities and linked the portable private library. Programs: unbound,

Added offline regression:
  usr.sbin/unbound/tests/forwarding.py

The final suite passed all of these against controlled loopback upstreams:
  - Local A, CNAME, PTR; incoming UDP/TCP.
  - Forwarded positive responses and CNAME chains.
  - Positive and negative cache hits verified with upstream request counters.
  - UDP truncation followed by outgoing TCP fallback.
  - Ordinary AAAA responses and CD/non-CD cache reuse.
  - Valid DNSSEC signatures with AD; corrupt signatures yield SERVFAIL;
    CD requests receive the otherwise rejected answer.
  - Prefetch issues a fresh upstream request.
  - Serve-expired answers during upstream failure.
  - Multiple forwarders with one unavailable, runtime forward_add changes.
  - Statistics, filesystem-protected Unix-socket control, reload, upstream change.
  - fast_reload after dnstap hook removal.
  - Outgoing TLS validates a private test CA and rejects hostname mismatch.
  - Removed directives/module names are rejected by unbound-checkconf.

Limits: no live public DNS verification; no forced exhaustive forwarder-selection
order; no production privilege-drop/chroot test; no remote-control TLS test;
no automatic trust-anchor-update or bootstrap runtime test; no full LAN ACL test.
Fixture resolver runs as the invoking user with username/chroot options disabled.
Test DNSSEC/TLS credentials are solely fixtures, valid until 2036. Runtime tests
need permission to create loopback sockets in a restricted Codex sandbox.

buildworld/buildkernel were NOT run. Portable Linux success does not establish
HalfBSD integration success; a suitable HalfBSD build environment remains needed.

REMAINING FEATURES AND NEXT STEPS

Still present: HTTPS server, QUIC, DNSCrypt, incoming TLS, cachedb/Redis,
EDNS Client Subnet/subnetcache, RPZ/response-IP, client views, authority zones,
zone-transfer/update machinery, stub zones, and general recursive resolution.
The whole objective is therefore NOT complete.

Reasonable next independent candidates are cachedb/Redis and subnetcache. Trace
configuration, callbacks, statistics, runtime control and reload first. Remove
each completely, regenerate outputs, compile and rerun retained-protocol tests.
Generic module callback plumbing remains shared with Client Subnet, including
reply-path helpers with no remaining Python/dynlib registrations; revisit it when
removing subnetcache rather than declaring all callback infrastructure gone.

Encrypted server removals need caller-level separation from outgoing TLS and
remote-control authentication. Policy/authority/view removals cross worker,
response, cache and reload paths and need dedicated review. Iterator recursive-only
paths have NOT yet been mapped for safe deletion. Keep forwarding selection,
retry/timeout, response scrubbing, DNSSEC subqueries and cache integration intact.

Mandatory catch-all forward-zone and no-recursion enforcement are NOT implemented.
They must eventually cover startup, reload and runtime forwarding changes, reject
missing upstreams and forward-first fallback, and return failure rather than
contacting root/authoritative servers when upstreams fail. Do not wholesale-delete
the iterator or claim that this first pass has made Unbound forwarding-only.

LIBRARY AND CONFIGURATION FINDINGS

libunbound is required by all four retained HalfBSD programs. unbound-anchor uses
its resolver API for DNSSEC bootstrap. Whole-tree Makefile search found no other
HalfBSD consumers, but this does not authorize deleting the library wholesale.
Portable unbound-host source/build support remains; HalfBSD does not install it.
Auxiliary API cleanup needs another consumer review.

Configuration migration has NOT been implemented. Target layout:
  /etc/unbound/unbound.conf     static configuration
  /etc/unbound/forward.conf     DHCP-derived upstreams
  /var/unbound/root.key         persistent mutable DNSSEC state
  /var/run                     runtime sockets and PID files

Existing setup still generates configuration under /var/unbound, including
control.conf and lan-zones.conf. Relevant integration paths are
usr.sbin/unbound/setup/local-unbound-setup.sh, contrib/openresolv/unbound.in and
libexec/rc/rc.d/local_unbound. Migration needs coordinated setup/resolvconf/rc,
installation, permissions and chroot handling, with existing-installation tests.
Do not break existing deployments merely to implement the target directory tree.

CAPSICUM INVENTORY, BEHAVIOR UNCHANGED

Runtime operations that will matter later: configuration rereads/include globbing
on reload; log reopen; CA/key/certificate reads when recreating TLS contexts;
control sockets/socketpairs and worker notification channels; PID-file lifecycle;
outgoing UDP/TCP/TLS socket creation for normal traffic, retries and anchor probes.

validator/autotrust.c reads managed anchor state, creates/writes/flushes temporary
files and renames them over root.key. These require directory/write capabilities.
unbound-anchor can fetch and replace bootstrap state using DNS and HTTPS.
Remaining authority-zone machinery adds runtime file/network operations until
removed. No sandbox behavior was introduced. Future capability-mode design must
account for reloads, mutable anchor state and ongoing socket creation.
